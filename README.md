# YouTube-Video-AI-Knowledge-Assistant



 # YouTube Knowledge Assistant

A playlist-based RAG (Retrieval-Augmented Generation) system. Give it YouTube videos, ask questions in **English, Hindi or Hinglish**, and get answers with **clickable, timestamp-accurate citations** that play the exact moment in the video.

## Features

- Ingests single videos or whole playlists (`yt-dlp`)
- Speech-to-text with `faster-whisper` (runs on CPU, no GPU needed)
- Timestamp-aware chunking (~45s chunks with overlap)
- Multilingual semantic search (`paraphrase-multilingual-MiniLM-L12-v2`) stored in a local Qdrant database
- Answers generated by Groq (`openai/gpt-oss-120b`) with optional Gemini fallback
- Answers in the language of the question, with inline citations like `[1]`
- Out-of-context questions are rejected ("not found in playlist")
- React UI with an embedded video player that jumps to the cited timestamp, plus an "Open on YouTube" button

## Architecture

```
YouTube URL / playlist
        |
     yt-dlp  (audio download)
        |
  faster-whisper  (transcript + segment timestamps)
        |
   chunking (start, end, text)
        |
  multilingual embeddings
        |
  Qdrant (local, ./qdrant_db)
        |
Question -> embed -> top-k search -> relevance filter
        |
   Groq LLM (Gemini fallback) -> answer + [n] citations
        |
 FastAPI  ->  React UI (video player at exact timestamp)
```

## Project structure

```
yt_rag/
  ingest.py          # download + transcribe + chunk + embed + store
  ask.py             # CLI chat + retrieval/LLM logic (reused by the API)
  api.py             # FastAPI backend
  delete_video.py    # remove a video's chunks (to re-ingest it)
  requirements.txt
  .env.example
  frontend/          # React (Vite) UI
```

## Prerequisites

- **Python 3.12 recommended** (very new versions such as 3.14 may lack prebuilt wheels for some packages)
- **Node.js** (LTS) for the frontend
- A free **Groq API key**: https://console.groq.com
- (Optional) a **Gemini API key** for fallback: https://aistudio.google.com/apikey
- Internet for the first run (models are downloaded once, ~1 GB)

ffmpeg is **not** required.

## Setup

### 1. Clone and create a virtual environment

```bash
git clone https://github.com/YOUR_USERNAME/youtube-rag-assistant.git
cd youtube-rag-assistant

python -m venv venv
# Windows
venv\Scripts\activate
# macOS / Linux
source venv/bin/activate

pip install -U pip
pip install -r requirements.txt
```

### 2. Configure environment variables

Copy `.env.example` to `.env` and fill in your keys:

```
GROQ_API_KEY=your_groq_api_key
GROQ_MODEL=openai/gpt-oss-120b
GEMINI_API_KEY=your_gemini_api_key      # optional
GEMINI_MODEL=your_gemini_model          # optional
WHISPER_MODEL=small
WHISPER_LANGUAGE=
```

- Write each value on its own line, with no quotes and no spaces around `=`.
- `WHISPER_MODEL`: `tiny` / `base` / `small` (larger = more accurate, slower on CPU).
- `WHISPER_LANGUAGE`: leave empty for auto-detect, or set `hi` / `en` to force a language.

Never commit `.env`. It is already in `.gitignore`.

### 3. Ingest videos

Pass one or more video or playlist URLs:

```bash
python ingest.py "https://youtu.be/VIDEO_ID_1" "https://youtu.be/VIDEO_ID_2"
python ingest.py "https://www.youtube.com/playlist?list=PLAYLIST_ID"
```

If you pass no URL, it ingests the 3 default demo videos defined in `ingest.py`.

Notes:
- Transcription runs on CPU and can take a while (several minutes per video).
- Already-ingested videos are skipped automatically.
- The terminal shows the detected language and a transcript sample so you can check quality.
- A `No supported JavaScript runtime` warning from yt-dlp is harmless for this project.

To re-ingest a video (for example with a better Whisper model):

```bash
python delete_video.py VIDEO_ID
python ingest.py "https://youtu.be/VIDEO_ID"
```

### 4a. Ask from the terminal

```bash
python ask.py
```

### 4b. Run the web app

Open two terminals.

**Terminal 1 (backend):**

```bash
# from the project root, venv active
uvicorn api:app --port 8000
```

Check: http://localhost:8000/health should return `{"status":"ok"}`.

**Terminal 2 (frontend):**

```bash
cd frontend
npm install
npm run dev
```

Open http://localhost:5173.

> **Important:** local Qdrant allows only one process at a time. Don't run `ingest.py`, `ask.py` and `uvicorn` together. Stop one before starting another.

## Example questions

| Type | Example |
|---|---|
| Single video | What is RAG? |
| Hinglish | RAG kya hota hai? |
| Cross-video | How are machine learning and RAG related? |
| Out of context | What is the capital of Japan? (returns "not found in playlist") |

## Configuration (in `ask.py`)

| Setting | Purpose |
|---|---|
| `TOP_K` | Number of chunks retrieved |
| `STRONG_SCORE` | Minimum best-match score, below this the question is treated as out of context |
| `MIN_SCORE`, `RELATIVE_GAP` | Filter weak chunks |
| `USE_GEMINI_FALLBACK` | Use Gemini if Groq fails |
| `DEBUG` | Print retrieval scores for tuning |

If you change the playlist language or embedding model, re-tune `STRONG_SCORE` using `DEBUG = True`.

## Limitations

- Transcript quality depends on the Whisper model. Hindi and Hinglish audio is noisy with `tiny`/`base`; `small` is better but slower on CPU.
- Cross-language retrieval (English question, Hindi transcript) gives lower similarity scores than same-language retrieval.
- Some videos block embedding; use the "Open on YouTube" button in that case.
- Local Qdrant is single-process; for multi-user hosting use a Qdrant server.
- The LLM answers only from retrieved excerpts, so answers can be incomplete if retrieval misses the relevant moment.
